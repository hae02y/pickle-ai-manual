# 09. 실전 요청 예시

아래 문장은 그대로 복사해 쓰기보다 날짜, 장소, 예산, 제공할 정보를 자기 상황에 맞게 바꾸세요. 실제로 사용하지 않은 기능의 성공을 보장하는 예시는 아닙니다. Pickle이 처리할 수 있다고 안내한 웹 작업·전화·기억·예약 작업을 바탕으로 만든 **권장 요청 형식**입니다. [작업 위임 안내](https://www.pickle.com/help/tasks/delegate)

요청문에서 가장 중요한 것은 **AI가 스스로 결정할 범위와 다시 물어야 할 지점**입니다. 후보 검색이라면 원하는 조건과 비교 방식이면 충분합니다. 예약·구매라면 승인받을 금액과 취소 조건, 완료를 확인할 외부 기록까지 적으세요.

## 제안 카드에서 시작하기

![피클의 제안 카드가 채팅으로 옮겨진 예시 화면](https://www.pickle.com/help-center/screens/tasks-explore-suggestions.webp)

*이미지 출처: [Pickle 공식 도움말 ― 둘러보기의 제안 카드 쓰기](https://www.pickle.com/help/tasks/explore-suggestions), 2026년 11월 2일 확인. 제안 내용은 사용자와 시점에 따라 달라집니다.*

무엇을 부탁할지 떠오르지 않으면 아래쪽 **둘러보기** 탭의 제안 카드를 살펴보세요. 카드를 열어 내용을 읽고 **시작하기**를 누르면 그 문장이 기본 채팅으로 보내집니다. 보내기 전에 이 장의 예시처럼 날짜·예산·완료 조건을 덧붙여도 좋습니다. 제안 카드는 바로 일을 맡기는 출발점이므로, 예약과 결제는 뒤이어 나오는 조건 카드를 다시 확인하세요. [둘러보기 도움말](https://www.pickle.com/help/tasks/explore-suggestions)

## 1. 후보만 찾기

> “토요일 오후 6시쯤 2명이 갈 식당 후보 세 곳을 찾아줘. 1인당 예산은 5만 원 이내야. 위치, 가격대, 예약 가능 여부와 취소 조건을 표로 비교해 줘. 연락이나 예약 확정은 하지 마.”

처음 맡기는 일이라면 후보 찾기부터 시작하세요. 이 문장은 검색과 비교만 허용합니다. 결과표에서 가격과 취소 조건이 비어 있다면 “모른다”로 두고, 확인되지 않은 값을 사실처럼 채우지 말라고 덧붙일 수 있습니다.

이 후보 찾기에서 문의·예약으로 넘어가는 판단 과정과 결과 확인표는 [17. 첫 작업 맡기기](https://wikidocs.net/493290)에 정리했습니다.

## 2. 전화로 가능 여부만 확인하기

> “이 식당에 토요일 오후 6시 2명 자리가 있는지 문의해 줘. 내 이름과 연락처가 필요한지 먼저 알려 줘. 자리가 있어도 예약 확정이나 예약금 결제는 하지 마.”

전화는 상대방에게 사용자 대신 말하는 행동입니다. 이 예시는 **빈자리 확인**까지만 맡기고, 이름·연락처 전달이나 예약 확정은 다시 묻게 합니다. 통화 뒤에는 왼쪽 메뉴의 **추가 대화**에서 실제로 전달된 말과 통화 상태를 확인하세요. 응답 없음은 “빈자리 없음”과 다른 결과입니다. [추가 대화 보기](https://www.pickle.com/help/chat/other-chats)

## 3. 예약을 요청하기

> “후보 중 A 식당의 토요일 오후 6시 2명 자리를 예약해 줘. 예약금이 없고 취소 수수료가 없는 조건일 때만 진행해 줘. 조건이 다르면 승인 전에 다시 알려 줘. 완료 뒤 예약 번호와 확인 화면을 보여 줘.”

이 문장에서는 예약금이나 취소 수수료가 없을 때만 진행할 수 있습니다. 현장에서 다른 조건을 제시하면 멈춰서 새 조건을 보여 달라고 한 이유가 여기에 있습니다. 승인 카드가 뜨면 날짜·인원·가격·취소 마감 시각을 읽고, 완료 뒤에는 식당이 보낸 확인 기록과 대조하세요. [작업 위임 안내](https://www.pickle.com/help/tasks/delegate)

## 4. 정기 요약 만들기

> “매주 월요일 오전에 이번 주 일정에서 내가 직접 결정해야 할 일만 요약해 줘. 다른 사람에게 메시지를 보내거나 일정을 바꾸지는 마.”

이 예시는 **요약**과 **대신 행동하기**를 분리합니다. 처음에는 읽기만 맡기고, 참석자에게 연락하거나 일정을 바꾸는 일은 별도 요청으로 다루세요. 피클 프로필의 **예약한 작업**에서 주기·다음 실행·기록을 보고, 프로젝트가 끝나면 일시정지하거나 삭제합니다. 실행할 때마다 계정의 사용량 한도를 쓸 수 있습니다. [예약 작업 도움말](https://www.pickle.com/help/tasks/scheduled)

## 5. 기억 바로잡기

> “내가 채식주의자라는 기억은 잘못됐어. 관련 기억을 보여 주고 수정하거나 삭제할 수 있게 도와줘. 앞으로 식당 추천에는 새 정보를 적용해 줘.”

기억을 고치라는 대화만으로 끝내지 말고, 피클 프로필의 **함께한 추억**에 실제로 어떻게 남았는지 확인하세요. “채식을 싫어한다”처럼 반대 방향으로 지나치게 일반화하지 않았는지도 살핍니다. 다음 식당 요청에는 그날의 조건을 다시 적으세요. [공식 소개](https://www.pickle.com/help/start/what-is-pickle)

## 6. 진행 중인 작업의 조건 바꾸기

> “진행 중인 식당 예약은 6시가 아니라 7시로 바꿔 줘. 이미 6시 예약이 확정됐다면 새 예약을 만들지 말고 먼저 상태와 취소 조건을 보여 줘.”

진행 중인 작업의 조건은 채팅에서 바꿀 수 있다고 안내됩니다. 다만 6시 예약이 이미 확정됐다면 새 지시는 기존 예약을 자동 취소하지 않습니다. **기존 예약 상태 → 변경 가능 여부 → 새 예약 필요 여부** 순서로 확인한 뒤 다음 행동을 정하세요. [진행 중인 일 확인하고 취소하기](https://www.pickle.com/help/tasks/check-and-cancel)

## 7. 작업을 멈추고 상태 확인하기

> “이 주문 작업을 중단해 줘. 결제와 주문이 이미 접수됐는지, 아직 남은 단계가 무엇인지 구분해서 알려 줘. 확인 전에는 다시 결제하지 마.”

작업 카드에서 중단해도 이미 접수된 주문은 남을 수 있습니다. 이 예시처럼 **중단 요청**과 **외부 접수 확인**을 함께 적으세요. 결제 여부가 불확실하면 재시도 여부를 결정하지 말고 주문·카드 내역을 먼저 확인합니다. [작업 취소](https://www.pickle.com/help/tasks/check-and-cancel), [결제 확인](https://www.pickle.com/help/tasks/confirm-before-payment)

## 요청을 만드는 공식

**목표 + 조건 + 결과 형식 + 금지할 행동 + 승인 시점 + 완료 증거**를 한 문장 또는 짧은 목록으로 적으세요. 모든 요청에 여섯 항목이 필요한 것은 아닙니다. 돈이나 다른 사람과의 약속이 걸리면 마지막 세 항목이 특히 중요합니다.

| 단계 | 독자가 채울 한 문장 |
| --- | --- |
| 시작 | “무엇을 언제까지 해 줘.” |
| 경계 | “이 금액·조건을 넘으면 먼저 물어봐.” |
| 확인 | “끝나면 확인 번호와 외부 기록을 보여 줘.” |

“식당을 예약해 줘”를 “토요일 6시, 2명, 예약금이 없을 때만 진행하고 조건이 달라지면 물어봐. 끝나면 확인 번호를 보여 줘”로 바꾸면 행동의 경계가 보입니다. 뒤의 문장을 더하는 이유는 작업 완료 메시지와 실제 예약 접수가 서로 다를 수 있기 때문입니다.

### 요청을 다듬는 두 번의 질문

1. **피클이 묻지 않고 정해도 되는 조건은 무엇인가요?** 예를 들어 후보를 세 곳으로 줄이는 일은 맡길 수 있지만, 예약금을 낼지는 직접 정할 수 있습니다.
2. **작업이 끝났다는 것을 어디에서 확인하나요?** 피클 채팅 밖에 있는 예약 내역, 확인 메일, 업체 기록을 하나 정해 둡니다.

이 두 질문에 답할 수 없으면 요청을 바로 실행하기보다 후보 찾기 단계로 좁히세요. 요청문이 충분히 상세해도 외부 사이트의 상태는 바뀔 수 있으므로 최종 화면을 다시 확인해야 합니다.

> **기술 분석:** 좋은 요청은 모델의 “추측할 자유”를 줄이는 입력 사양이기도 합니다. 목표, 제약, 허용된 행동, 승인 지점, 외부에서 확인할 완료 증거를 함께 적으세요. 반복 실행에 쓸 문장이라면 종료 날짜와 중복 방지 조건을 더하세요. 이 형식이 성능을 보장하지는 않지만 [12장](https://wikidocs.net/491191)의 조건 준수율과 외부 확정률을 측정할 수 있게 합니다.
