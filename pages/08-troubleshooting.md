# 08. 오류·중단·복구

AI가 “완료했습니다”라고 말했어도 외부 사이트에서는 실패했을 수 있습니다. 반대로 오류 화면이 떠도 예약·결제가 처리됐을 수 있습니다. [Pickle 약관](https://www.pickle.com/ko/terms-of-service)은 웹사이트 변화, 결제 실패, AI의 실수 때문에 결과를 보장할 수 없다고 밝힙니다.

## 먼저 상태를 구분하세요

| 보이는 상황 | 먼저 확인할 것 | 다음 행동 |
| --- | --- | --- |
| 작업이 계속 진행 중 | 작업 카드와 최근 메시지 | 기다리거나 필요한 추가 정보 제공 |
| 로그인·인증 요청 | 요청한 사이트가 맞는지 | 보안 카드나 사용자 직접 인증 사용 |
| 오류·중단 보고 | 외부 사이트의 예약·주문 내역 | 처리되지 않았을 때만 재시도 |
| 완료 보고 | 예약 번호·확인 메시지·결제 내역 | 조건 대조 후 완료로 기록 |
| 잘못된 결과 | 외부 업체의 취소·수정 경로 | Pickle 작업 중단과 별도로 정정 |

## 중단 요청

“지금 작업을 멈춰 줘. 이미 외부에서 확정된 단계와 남은 단계를 나눠 알려 줘”라고 요청하세요. Pickle 약관은 작업이나 예약 행동을 중단할 수 있지만, 제삼자 서비스에서 이미 끝난 단계는 남는다고 설명합니다. [서비스 약관](https://www.pickle.com/ko/terms-of-service)

## 재시도 전 3단계

1. **외부 상태 조회:** 상대 사이트의 예약·주문·결제 내역을 확인합니다.
2. **중복 위험 점검:** 같은 요청이 다시 실행되면 예약·주문이 두 개 생길 수 있는지 봅니다.
3. **조건 재확인:** 가격·날짜·대상·취소 규칙이 바뀌었다면 새 카드에서 다시 승인합니다.

이 절차는 매뉴얼의 권장 방법입니다. Pickle의 자동 재시도 동작을 설명하는 것은 아닙니다.

## 문의 기록 양식

| 항목 | 적을 내용 |
| --- | --- |
| 요청 | 무엇을 언제 맡겼는가 |
| 기대 결과 | 어떤 조건으로 완료돼야 했는가 |
| Pickle 보고 | 어떤 상태와 증빙을 보여 줬는가 |
| 외부 상태 | 업체 사이트·결제 내역에는 무엇이 남았는가 |
| 이미 한 조치 | 중단, 재시도, 업체 문의, 취소 여부 |
