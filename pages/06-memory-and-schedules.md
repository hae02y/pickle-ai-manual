# 06. 기억과 예약 작업

Pickle은 대화에서 배운 내용을 기억합니다. 사용자는 피클 프로필의 **함께한 추억**에서 그 내용을 읽고 수정하거나 삭제할 수 있습니다. 기억은 다음 부탁을 이해하는 데 도움이 되지만, 예전 대화가 새 예약이나 결제를 승인한 것은 아닙니다. [공식 소개](https://www.pickle.com/help/start/what-is-pickle)

한 번 채식 메뉴를 골랐다는 사실이 “항상 채식 식당을 원한다”는 기억으로 굳어지면, 다음 추천이 틀어질 수 있습니다. 기억을 볼 때는 **사실인지**, **지금도 유효한지**, **어떤 상황에서만 쓸지**를 구분하세요.

## 기억을 다루는 방법

| 상황 | 할 일 |
| --- | --- |
| 자주 유지되는 선호 | 적용할 상황을 덧붙임. 예: “업무 미팅 때는 조용한 곳” |
| 한 번만 적용된 조건 | 장기 선호처럼 적혔다면 수정. 예: “이번 주 금요일만 불가” |
| 틀린 사실 | 함께한 추억에서 수정하거나 삭제 |
| 민감하거나 불필요한 정보 | 저장 필요성을 따져 삭제 여부 결정 |

“창가 자리를 좋아한다”는 기억은 후보를 고를 때 쓸 수 있습니다. 하지만 창가 자리의 추가 요금이나 취소 수수료까지 받아들였다는 뜻은 아닙니다. 실제 예약은 그때의 조건 카드에서 다시 판단하세요.

| 기억에 적힌 문장 | 더 정확하게 다듬을 질문 |
| --- | --- |
| “조용한 식당을 좋아함” | 매번 그런가, 업무 미팅 때만 그런가? |
| “금요일에는 시간이 없음” | 이번 주만인가, 반복 일정인가? |
| “카드로 결제함” | 결제 선호와 결제 권한을 혼동하고 있지 않은가? |

좋아하는 조건 자체가 맞다면 적용 범위만 좁혀도 됩니다. 잘못된 사실이나 불필요한 민감 정보라면 삭제까지 검토하세요.

### 기억을 점검하는 순서

화면 위쪽의 피클 모습이나 이름을 눌러 프로필을 열고 **함께한 추억**을 확인하세요. 오래된 선호를 고친 다음에는 같은 주제로 새 질문을 해 반영 여부를 살핍니다. 연결 계정을 끊어도 대화나 기억에 이미 들어간 내용은 별개로 남을 수 있습니다. 연결 해제와 기억 정리를 각각 확인하세요. [화면 구성](https://www.pickle.com/help/start/app-layout), [Pickle 개인정보 설명](https://www.pickle.com/how-your-pickle-protects-your-privacy)

## 예약 작업 관리

![피클 프로필의 한 일·예약한 작업·함께한 추억 탭](https://www.pickle.com/help-center/screens/tasks-check-and-cancel.webp)

*이미지 출처: [Pickle 공식 도움말 ― 진행 중인 일 확인하고 취소하기](https://www.pickle.com/help/tasks/check-and-cancel), 2026년 11월 2일 확인. 그림은 프로필의 ‘한 일’ 탭 예시이며, 위쪽 탭에서 예약한 작업과 함께한 추억으로 이동합니다. [화면 구성 도움말](https://www.pickle.com/help/start/app-layout) 참고.*

공식 도움말에 따르면 Pickle은 한 번 또는 매일·매주·매월 반복되는 예약 작업을 수행할 수 있습니다. 기본 채팅에서 “매주 월요일 아침에 이번 주 일정을 요약해 줘”처럼 요청할 수 있습니다. 화면 위쪽의 피클 모습이나 이름을 눌러 프로필의 **예약한 작업**으로 들어가면 일회성·반복·일시 중지된 작업이 나뉘어 보입니다. 각 작업에는 내용, 주기, 다음 실행까지 남은 시간이 표시됩니다. [예약 작업 도움말](https://www.pickle.com/help/tasks/scheduled)

| 관리 항목 | 확인 질문 |
| --- | --- |
| 실행 주기 | 한 번이면 충분한 일을 반복하고 있지 않은가? |
| 읽는 정보 | 매번 어떤 계정·자료를 읽는가? |
| 결과 전달 | 누구에게 어떤 내용이 보이는가? |
| 사용량 | 실행할 때마다 현재 플랜의 한도를 쓰는가? |
| 종료 | 언제 멈추거나 삭제할 것인가? |

사용자가 부탁한 예약 작업은 실행할 때마다 주간 사용량을 쓰며, 한도에 도달하면 초기화 전까지 실행을 건너뛸 수 있다고 [영어 사용량 안내](https://www.pickle.com/help/credits/usage-credits)는 설명합니다. 단, 지역·플랜에 따른 적용 상태는 계정 화면에서 확인하세요. 중요한 마감에는 원래 캘린더나 서비스의 알림도 함께 두는 편이 안전합니다.

아침 브리핑의 **기본 활성 상태는 공식 문서끼리도 모순**됩니다. [영어 제품 소개](https://www.pickle.com/help/start/what-is-pickle)는 기본으로 매일 보낸다고 쓰고, [예약 작업 안내](https://www.pickle.com/help/tasks/scheduled)는 본문에서 기본 설정된 작업으로 소개하면서 같은 페이지의 ‘알아두세요’에서는 기본으로 꺼져 있다고 씁니다. [사용량 안내](https://www.pickle.com/help/credits/usage-credits)도 꺼짐으로 설명합니다. 어느 문구를 모든 계정의 사실로 단정할 수 없으므로, **예약한 작업 목록에서 브리핑의 실제 활성 상태·다음 실행·기록**을 확인하세요.

반복 작업은 오늘 쓴 문장을 다음 주의 새로운 데이터에도 적용합니다. “매주 월요일 일정 요약”과 “매주 월요일 참석자에게 일정 안내”는 같지 않습니다. 후자는 매번 다른 사람에게 메시지를 보낼 수 있습니다. 실행 주기와 읽을 자료뿐 아니라 **외부로 보낼 말, 승인 지점, 끝낼 날짜**까지 정하세요.

| 독자의 질문 | 확인할 곳 | 판단 기준 |
| --- | --- | --- |
| 이 작업을 누가 만들었나? | 예약한 작업의 내용과 대화 기록 | Pickle이 맡긴 일을 추적하려고 자체 생성할 수도 있으므로, 모르는 작업은 목적을 확인 |
| 지난번에 실행됐나? | 해당 작업의 **기록** | 실행 보고와 실제 캘린더·메일 등 결과를 함께 대조 |
| 다음번에도 필요한가? | 다음 실행 시각·주기 | 휴가·프로젝트 종료 등 상황이 바뀌면 일시정지하거나 삭제 |
| 한도 때문에 건너뛰었나? | 기록과 플랜 카드 | 빈 결과를 “할 일 없음”으로 해석하지 않고 사용량 상태 확인 |

작업을 눌러 상세 화면을 열면 **일시정지**, **수정**, **삭제**, **기록**을 선택할 수 있습니다. 예를 들어 휴가 중에는 주간 업무 요약을 일시정지하고, 복귀 후 다시 시작합니다. 삭제는 더 이상 필요 없는 작업에 쓰고, 지난번에 실제로 실행됐는지는 기록에서 확인하세요. 사용자가 멈추거나 지운 작업은 피클이 임의로 다시 실행하지 않는다고 안내합니다. [예약 작업 도움말](https://www.pickle.com/help/tasks/scheduled)

> **기술 분석:** 기억은 단순 보관과 다릅니다. 무엇을 장기 선호로 저장할지, 관련 작업에서 어떻게 찾아 쓸지, 잘못된 기억을 어떻게 수정할지가 모두 중요합니다. Pickle의 내부 검색·요약 알고리즘은 공개되지 않았습니다. 예약 작업은 정해진 시점에 AI 작업을 다시 실행하는 기능으로, 오래된 조건이나 권한이 반복 적용될 수 있습니다. [12장](https://wikidocs.net/491191)의 기술 설명과 [15장](https://wikidocs.net/491194)의 실행 기록 점검을 참고하세요.
